# 单种子续测：baseline、创新可行性与下一步建议

更新时间：2026-10-12。本文服务于选题和 demo 决策。遵循当前约束：单训练种子、短周期、优先验证和可视化，不扩展多随机种子。输入为本项目的真实训练、逐候选预测与仿真输出；范围为三个重点方向。

## 1. 这轮新增了什么

| 方向 | 新增实验 | 数据边界 | 结果 |
|---|---|---|---|
| YOLO 无人机检测 | 冻结 YOLO11n，训练轻量候选复核器；比较目标局部裁剪和约 3 倍扩大裁剪 | 只读 `paper_v1` train/validation；792 验证帧；未读取 calibration/test | 两个版本都没有通过预设门槛，暂不进入正式主方法 |
| 60 GHz 调度 | 在同一外生轨迹上补充 fixed beam、validation beam、严格 RR/TDMA、feedback MAB | 两个已观察场景，各一个 environment seed=40000；不改变锁定的 800 行正式评价 | 用户级先验在高负载场景有正向信号，但跨场景仍有 trade-off；RR 适合作为直观下界 |
| PA / DPD | 沿用已经完成的 GRU、uniform experts、envelope MoE、传统 MP/GMP 和有限标签适应 | APA A/B、DPA160；单种子完整训练与短适应 | MoE gate-only 被强对照否定，不建议继续堆门控 |

## 2. YOLO：二阶段复核器短测没有证明可行

基线是冻结的 YOLO11n seed0 best checkpoint。候选框由 YOLO 产生，复核器是 19,105 参数的小 CNN，训练 4 轮，使用 4,411 个候选（3,814 正例、597 负例），平衡采样。正样本为候选框与 DRONE 标注 IoU≥0.30，负样本为同帧高分 hard negative。两种输入只差在裁剪范围：目标局部，或目标外扩约一倍边长的上下文。后者仍是单裁剪、单分支，尚未实现最初设想的双分支融合。

级联规则固定为 YOLO confidence≥0.25 且 verifier probability≥0.50；只有原来检出的候选能被保留，复核器不能把低分候选提升为新报警。首版把 classifier 最大分数当帧报警的表格已撤回；下表来自固定权重的纠正重评价，没有重训。

验证集结果如下：

| 方法 | presence recall | 负帧 FPR | F1 | 解释 |
|---|---:|---:|---:|---|
| YOLO | 0.956 | 0.039 | 0.957 | 当前短测 baseline |
| YOLO + EMA(0.6) | 0.938 | 0.025 | 0.955 | 经典时序后处理，只作参照 |
| YOLO + target crop cascade | 0.953 | 0.039 | 0.956 | 减少 1 个无人机检出，未减少误报 |
| YOLO + expanded 3x crop cascade | 0.755 | 0.022 | 0.849 | 滤掉 7 个鸟类误报，同时减少 77 个无人机检出 |

预设目标是召回下降不超过 1 个百分点、同时直升机 FPR 下降约一半。两个版本都没有达到：target crop 召回只下降 0.26 个百分点，但不减误报；扩大裁剪召回下降 20.05 个百分点。target 和扩大裁剪的直升机误报都是 8/72 帧（11.11%），没有改善；EMA 只把直升机 FPR降到7/72（9.72%），但无人机召回也降到93.75%。因此不能在 PPT 中说当前复核器有效。这个 4 轮短测否定的是当前小 CNN、数据和固定操作点的实现，不能否定所有级联或真正双分支方案。

产物：`experiments/runs/vision_single_verifier_probe_v1/cascade_reval_v1/README.md`、`summary.json`、`validation_predictions.json`、`validation_verifier_montage.jpg`。逐候选接受规则与帧指标重算一致，权重哈希未变。训练候选只来自 train，复核器在 validation 上判断，不能把 validation 数字当最终 test 泛化。

对 YOLO 的正式建议：保留 YOLO11n + EMA 作为可播放 baseline；若仍选视觉，下一步应改成有明确负类监督的“无人机/直升机/鸟/飞机”轻量分类或检测头，并在新增未见视频上确认，而不是继续微调当前二阶段复核器。当前最可靠的 contribution 叙事是“针对直升机混淆的负类建模”，方法本身尚未验证成功。

## 3. 60 GHz：结构化用户先验值得保留，但只能称候选

正式锁定 baseline 仍是：标准 PPO 360k、PPO 历史训练 seed 对照、fixed beam2、validation-selected beam3、作者 scheme-4 反馈型 Thompson/MAB、privileged greedy 诊断；4 个场景×20 个环境 seed，共 800 行评价。正式报告见 `experiments/runs/rl_paper_baseline_locked_v1/REPORT.md`。

新增补充固定同一外生轨迹，加入严格 RR/TDMA 和 feedback MAB，修正版结果在 `experiments/runs/rl_short_supplement_v2/REPORT.md`。关键数值（吞吐 Gbps / 平均队列包/UE / pending%）是：

| 场景 | anchor PPO | continued PPO | user-marginal prior | fixed beam2 | RR/TDMA | feedback MAB |
|---|---|---|---|---|---|---|
| demo12 高负载 | 1.056 / 5903 / 4.705 | 1.067 / 3891 / 3.508 | **1.088 / 3495 / 1.747** | 0.707 / 50559 / 35.057 | 0.700 / 51839 / 35.645 | 0.751 / 41552 / 29.917 |
| demo13 | 1.001 / 1567 / 1.008 | 1.006 / 1049 / 0.626 | 1.001 / 1197 / 0.490 | 1.005 / 788 / 0.210 | 0.944 / 9078 / 6.531 | 1.003 / 612 / 0.154 |

用户级先验只约束用户选择，保留同一用户下 beam/relay/tracking 的自由度。相对同预算 continued PPO，demo12 的吞吐约 +1.96%、平均队列约 −10.2%、pending −1.76 个百分点；demo13 吞吐约 −0.48%、平均队列约 +14.2%，但 pending −0.136 个百分点。这个结果支持一个可讲清楚的机制假设：全动作先验可能过度约束策略，用户边缘先验更轻；但它不是跨场景稳定胜出，不能写成普遍改进。

RR/TDMA 不是新算法，也不是正式性能排名方法。它的价值是 PPT 中直观展示“只轮转一个 UE、固定一个 beam 会造成高负载队列爆炸”，帮助解释为什么需要联合调度。feedback MAB 有在线 2000 槽后验更新，与离线 PPO 的信息和预算不完全匹配，只作补充参照。

对 RL 的正式建议：若选智能通信网络主题，保留“结构化用户级先验”作为主 contribution 候选；正式实验至少要冻结一套新场景和评价协议，再补少量必要对照。当前结果只证明值得继续，不证明最终有效。demo 视频用于解释一条轨迹里的节点、beam、UE、relay、队列和动作，结论必须以正式汇总表为准。

## 4. PA / DPD：当前 MoE 创新应停止

PA 方向的 baseline 已完整跑通 OpenDPD APA_200MHz 前向建模与 DPD 流程，并补充 MP/GMP 传统参考。当前源域 APA A 的测试 NMSE：GRU −38.9030 dB，uniform experts −38.9841 dB，envelope MoE −38.9875 dB；MoE 相对 uniform experts 只有约 0.0034 dB。A→B 的 4096 标签适应中，GRU full −38.2083 dB，MoE full −38.0225 dB；只更新 gate 的 MoE 为 −24.4448 dB，明显弱于只更新 GRU 输出头的 −33.5558 dB。

因此不能把“加入 MoE gate”作为已验证创新。若最后选择 PA，应改成“有限测量条件下跨采集适应与更新位置比较”，并明确当前是 PA 前向 surrogate，不是硬件 RF 实测 DPD 线性化。PA demo 中的补偿输出由冻结 surrogate 预测，不能写成真实硬件 ACLR/EVM 收益。

## 5. 选题与正式实验决策

根据这次可行性结果，按“当前贡献是否已有正向信号、可完成性、课程相关性和PPT”重新排序：

1. **60 GHz 调度**：最贴课程主题，用户级先验有可讲的局部信号，且仿真、曲线和回放均已具备；需要清楚解释 reward、场景依赖和吞吐—积压的取舍。
2. **YOLO 视觉**：展示最直观，失败模式也最清楚；但当前复核器尚未成功，需要验证有明确负类监督或时序证据的新方案。
3. **PA / DPD**：流程最可控，但现有 MoE 贡献已被否定，换问题后需要重新组织故事。

如果队伍更看重“当前就能做出一个完整、可解释的 contribution”，我建议优先选 60 GHz 用户级结构化先验；如果更看重汇报视觉冲击并愿意再做一轮负类建模，选 YOLO。两者都不需要把大模型 finetune 作为前提。

## 6. 三类 demo 到底说明什么

- **YOLO**：左侧原始视频，右侧是同帧预测；绿色框是真实标注，红色框是模型预测。无人机片段展示检出，鸟/飞机展示负例，直升机展示主要失败模式。时间线里的 EMA 是减少报警抖动的经典后处理，不是新网络结构。
- **60 GHz**：同一仿真外生轨迹的动作回放，显示节点、UE、beam、relay、队列和传输。视频用于说明策略行为与失败机制；单条轨迹不能替代正式统计，也不能证明 PPO 或用户先验普遍优于所有方法。
- **PA**：真实 PA 输出 I/Q、模型预测和残差曲线；NMSE 越负越好。DPD 画面使用冻结 PA surrogate 预测补偿效果，属于前向建模闭环演示，不是再次采集的硬件射频测量。
